# 是石科技 · 双板块视频播控互动台 V1

> 当前版本仅用于客户体验测试，不作为验收依据或生产放行版本。现阶段只验证单 Pad → 单 TV 的局域网体验链路，不得据此认定双 Pad → 双 TV 固定通道隔离已经完成。

独立于 ROMS CPU / GPU 系统的 Xiaomi Pad 8 Pro 3:2 横屏播控程序。总览采用 Three.js / WebGL 实时轨道场景，并在同一套播控内核中承载 `成果案例` 与 `产品介绍` 两个固定频道。本期测试环境由 Pad 控制端与电视播放端组成；Pad 本机不加载或播放视频。

## 内容板块

- `成果案例 / SUCCESS CASES`：按最新目录编号为互联网、大模型、航空航天、高端制造、科研院所、海洋模拟、AI FOR SCIENCE；共 14 个可播项目。
- `产品介绍 / PRODUCT INTRODUCTION`：九个产品节点、十一部影片；PRODUCT-03 含三集。

## 交互

- Pad 01 固定进入 `成果案例`，Pad 02 固定进入 `产品介绍`；现场操作员不需要也不能在 Pad 上跨频道切换。
- 拖动空白区域：旋转完整三维星系；选中连接线上的小飞船沿曲线飞向当前内容星球。
- 单击任意内容星球：聚焦该星球，并进入全屏电视播控面板；Pad 本机不播放媒体。
- Pad 播控页：支持播放 / 暂停、原速 / 2× / 4×、静音、上一项、下一项和返回总览；进度仅显示控制服务的权威状态，不允许拖动。
- Pad 的上述指令通过局域网控制服务同步给电视端；电视端从品牌待机画面淡入对应视频，停止后淡回待机。
- 控制服务维护权威进度锚点、播放实例、playlist item 与命令序号，并以 500ms 状态流同步给 Pad 和电视；电视端按偏差进行柔性追帧或强制对时。
- 20 秒无操作：进入自动巡航，仅轮换高亮，不自动播放影片。
- 普通视频播放完成：停留在重播 / 下一项 / 返回总览；PPT 页面 MP4 在电视端持续循环，直到 Pad 发出上一项、下一项或退出。

当前本地素材库的 25 个 playlist 播放项已全部落位：11 个 PPT 页面循环 MP4、3 支成果案例视频、11 支产品视频。两个含 GIF 的页面已保留动态帧。**Git 仓库不包含这些 MP4 或原始 PPTX**；克隆源码后仍需按 `public/videos/README.md` 补齐独立媒体包。小米平板部署流程见 `docs/Xiaomi_Pad_部署说明.md`。

## 源码与媒体验证的区别

`test:orbit`、`test:standby`、`test:sync`、`test:sites` 为源码/协议检查；`test:media`、`content:check`、`media:qc` 是媒体落位后的集成检查，缺少配套 MP4 时会报告缺件。不要把源码仓库克隆成功理解为视频已经交付。

`media-build/` 为本机转码中间文件，不进入 Git；客户包需按当前 25 项 playlist 精确打包，不包含已弃用的旧槽位。新增客户包 / Release 需单独构建和验证。

## 本地运行

```bash
npm install
npm run dev
```

生产验证：

```bash
npm run build
npm run test:sites
```

局域网平板预览：

```bash
npm run preview:pad
```

本期 Pad / TV 双端测试环境：

```bash
npm run testenv:prepare
npm run testenv
```

- Pad 01（成果案例）：`http://<主机IP>:4175/pad`
- Pad 02（产品介绍）：`http://<主机IP>:4175/pad02`
- 电视：`http://<主机IP>:4175/tv`
- 视频槽位检查：`npm run content:check`
- 媒体编码 / GIF 动态检查：`npm run media:qc`
