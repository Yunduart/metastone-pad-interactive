# Pad 播放控制与同步修订｜2026-08-31

> 2026-09-03 增量决定：Pad 为纯控制端，不再挂载本地 `<video>`，也不再发送本地媒体 `SYNC` 样本。控制服务以 500ms 状态流向 Pad/TV 发布权威进度；电视/播放盒浏览器是唯一媒体渲染与纠偏端。下文旧的“Pad 每 500ms 发送播放状态”已被本条取代。

## 产品决定

- Pad 定位为播放遥控器，不承担时间轴精确跳转。
- 播放进度保留为只读状态展示，不允许拖动。
- 视频控制：播放、暂停、原速、2×、4×、静音、上一条、下一条、退出。
- 每次切换新视频默认恢复原速，避免用户在未知状态下进入 2×/4×。

## 同步规则

- 控制服务每 500ms 向 Pad 与电视发布当前 `progress / playing / muted / playbackRate / itemIndex / duration / loop`；Pad 只接收状态并发送离散控制命令。
- 每次播放创建唯一 `playbackId`；每条 Pad 指令带递增 `clientSequence`。
- 控制服务维护权威进度锚点，并拒绝同一控制端的旧序号指令。
- 网页播放端偏差超过 400ms 时直接对时；80–400ms 时短暂微调播放速率；进入 80ms 内恢复用户选择的基础倍速。
- 暂停状态偏差超过 40ms 时直接校正，避免恢复时从旧位置继续。

## 验收口径

1. Pad 页面不存在可拖动的 range/seek 控件。
2. 原速、2×、4×只能单选，Pad 与网页端显示和执行一致。
3. 播放中服务端进度持续推进；暂停后保持不变。
4. 旧播放实例或乱序指令不得覆盖当前状态。
5. 真机局域网验收目标：常态偏差不大于 150ms，暂停/倍速切换响应不大于 200ms，断线恢复不大于 2s。

## 状态边界

- 真实 Xiaomi Pad、电视播放端、现场网络连续运行仍需独立验收；完成前生产状态保持 NO-GO。
