## 3. 目标任务确认的程序影响

| 层面 | 只读影响判断 |
|---|---|
| 数据模型 | 从单一 `domain.video` 演进为 `catalog → topic/product → mixed-media playlist → item`。 |
| 状态机 | 需覆盖 PLAYLIST_READY、ITEM_LOADING、IMAGE/SLIDE_SHOWING、VIDEO_PLAYING、ITEM_END/WAIT_NEXT、SESSION_END 及异常恢复。 |
| 命令协议 | 需增加 OPEN_TOPIC、NEXT_ITEM、PREV_ITEM、JUMP_ITEM、EXIT，并保留视频命令；命令必须带会话/条目标识且幂等。 |
| 双端隔离 | Pad01 固定 CASES，Pad02 固定 PRODUCTS；controller、channel、catalog、target、session 不得串控。 |
| 媒体渲染 | 播放端必须支持图片、PPT 转图页和视频；现场不打开原生 PPT。 |
| 异常恢复 | 需处理离线、错通道、重复命令、旧版本、素材缺失、加载/解码失败、超时、自动播放受阻与重连快照。 |
| 验收 | 必须用两个真实 Pad 和两个独立目标播放端验证不串控；单机页面不构成现场验收。 |

## 4. 目标任务确认的现有 V1 差距

1. 当前 `/pad` 允许在成果案例与产品介绍之间切换，不满足两台 Pad 固定频道。
2. 当前 `domains.js` 仍是一个主题对应单视频，并硬编码旧 CASE 顺序和 PRODUCT 占位。
3. 当前服务端只有单一全局 `controlState` 和公共 SSE 广播，缺少双端 controller/channel/target/session/item 隔离。
4. 当前命令仅覆盖 PLAY/PAUSE/RESUME/SEEK/MUTE/STOP；上一项/下一项切的是主题，不是 playlist item。
5. 当前电视端只有视频渲染，没有图片/PPT 转图、逐项加载状态和完整恢复策略。
6. 视频结束约 8 秒回退、约 100 秒无操作退出属于旧原型临时值，尚未经客户确认。
7. ROMS 归属、科研院所最新版、0714/20260817 替换关系、案例顺序、产品映射、GIF/视频触发和结束策略仍未闭环。
8. V0.2 第 01 屏为评审总览，不是已批准的端侧首页；1920×1200 也不是现场参数确认。
9. 历史单 Pad—单 TV 原型通过不能替代双 Pad、双目标、混合媒体和现场验收。
